# Repository instructions

- Keep the official protocol: the official π0.5 co-train checkpoint (step 29999, `repo_id: RoboTwin_lerobot_v30`), the 50 tasks of `env_cfg/eval/all_tasks.yml`, `demo_clean` and `demo_randomized`, 100 accepted episodes per job, `expert_check=true`, CLI seed 0, the per-task step limits, native 50-step chunks, 10 flow steps and an eval video per episode. Do not change precision, samples per pixel, denoising, flow steps, seeds, step limits, instructions or episode counts to gain speed. Default to 8 GPUs when the GPU count is unspecified.
- Do not modify upstream RoboTwin or XPolicyLab files. Put changes in `evalopt/` (wrappers, or minimal-difference copies of upstream functions with each change marked `EVALOPT`) behind an `EVALOPT_*` switch that is off by default. `evalopt/README.md` has the diff commands that check the two existing copies against upstream.
- Every change must be E0: run `scripts/evalopt/run_pair.sh` and `python evalopt/compare_arms.py <out>` and require every episode to match (seed, instruction, success, steps, policy queries, consumed observations, action chunks, video frames) before looking at speed. Both arms load the same pinned autotune file and, for whole tasks, replay the same expert-check record. Changes of the random-number draw order (E1, e.g. splitting a job's episodes over processes) and changes of what is produced (deferred video) need an explicit decision by the user.
- The headline 4.38× (73.5 → 16.8 h on 8× H20) is an estimate from `evalopt/full_estimate.py` (6 of 100 jobs measured, 8% of the steps, leaderboard-based step counts, replayed expert checks), not a measured full run; GPU time is 4.21×. Present it that way. Per-task bars and the 96% ceiling figure are measured on smoke-scale runs. The deferred-video mode (`EVALOPT_NO_VIDEO`) is optional, its videos were checked on 6 episodes only, and it is not the default.
- The launchers are the measured scripts with workspace paths replaced by `scripts/evalopt/env.sh`; they were not re-run after that change. Run one short `run_pair.sh` case before trusting them on a new machine.
- Treat a job as invalid and rerun it if any log contains `Policy rollout error`, `env error before first action` or `Failed to generate episode instruction`, or if its episode count differs from `--test_num`; the official loop silently counts rollout exceptions as failures. Give every worker an exit timeout, start render workers staggered, and never use `num_workers > 1` with π0.5.
- Record the XLA autotune file anew for any other GPU model, driver or JAX version; the shipped file is for H20 with JAX 0.5.3.
- On shared hosts, respect GPU locks and other users' jobs; never stop another user's process; check that a port is free and that the listener is yours. Do not edit a running shell script in place.
- Use public code, checkpoints and assets only. Never commit checkpoints, simulation assets, expert-check records with local paths, eval videos, logs, run directories, credentials, private paths or per-file data listings. Put new experiments in a new dated directory with the source commit, environment versions and hardware.
